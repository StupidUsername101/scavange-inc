# Four-limb ML audit status

This file records contracts that have been traced end-to-end so later audits can focus on remaining unknowns instead of repeatedly rechecking settled plumbing.

Last static audit: 2026-08-08. Godot/Jolt runtime tests still need to be executed on a machine with Godot installed.

## Verified correct in code

- **Direct action ownership:** the policy has exactly four independent controls per limb: hip elevation, horizontal hip sweep, knee bend, and grip. There is no gait, walk, turn, climb, or grab macro layer between PPO and the physical actuators.
- **Action routing:** all 16 outputs have stable unique indices and reach the intended joint/end-effector. Grip commands are not included in the joint-command-spam reward.
- **PPO rollout lineage:** the limb trainer already enforces its on-policy boundary correctly: rollout collection is disabled while a background optimizer update is in flight, transitions from that window are not admitted, the optimized policy is synchronized before collection resumes, and active workers are resampled from the adopted policy. The stale sibling-policy regression found in drone PPO is not present here.
- **Live target routing:** every limb decision rebuilds the current group target/objective, and the observation, obstacle probe, reward deck, success metric, and target-distance telemetry consume that same routed 3D objective. Worker state does not cache an obsolete target position across target moves.
- **Hip lift sign and workspace:** positive hip elevation means upward/recovery motion on all four authored slots. Profile v12 retains the additional positive-only recovery range without widening horizontal sweep.
- **Horizontal hip chatter mitigation:** horizontal hip target slew is independently limited while elevation and knee response remain faster. Core/limb self-collision exclusions are installed, so repeated self-contact is not an intended source of hip jitter.
- **Joint-force ownership:** the native SixDOF spring and explicit passive/controller torque are an intentional split, not duplicate full-strength springs. Active joint torque is applied as equal/opposite parent-child torque. The obsolete virtual stance-force fields have been removed from the active body/serialization contract; there is no hidden outward/vertical foot-force path.
- **Grip surface contract:** stock feet can grip `climbable` and `carryable` surfaces but do not silently world-anchor to `ground`. Live room walls and hidden evaluator walls expose `climbable` metadata.
- **Grip authority:** stock holding-force limits exceed body weight by a large margin. Spring/damper demand and holding-force capacity now scale together with activation, and breakaway requires a short sustained overload instead of one physics-frame spike. A legal acquisition near the latch-radius edge therefore does not immediately fail merely because engagement began at the threshold or arrived with a transient contact velocity.
- **Grip action semantics:** controlled grip uses the complete normalized action channel: `-1` releases, `0` is a neutral hysteresis hold request, and `+1` fully engages. The old flat negative half-space is gone.
- **Grip perception:** compatible surfaces are sensed before they enter the physical acquisition radius. Physical attachment still requires the smaller acquisition radius, so longer perception does not create telekinetic grabs.
- **Grip target observation:** the policy receives one coherent candidate-or-attachment target: presence, physical-terminal-surface-to-target offset, normal, and normalized distance. Before latch it points from the end-effector support point toward the compatible candidate surface; after latch it points between the owner-side material anchor and the real target anchor. Candidate-only metadata remains separate for reach shaping, so an attached grip no longer reports an anchor vector paired with “candidate absent / distance far.” An absent target is consistently zero offset + far/max distance.
- **Feature diagnostics:** the schema-14 feature-name table has one unique semantic name for every encoded scalar (420 total). The stale duplicate `turret_line_of_sight` entry that could invalidate the PPO feature audit has been removed and is covered by a uniqueness/count regression test.
- **Target geometry:** a limb navigation marker denotes the actual support/destination surface. The coordinator converts it to a core goal one authored standing height above that surface; the drone-only hover offset is not applied to limb targets.
- **Ground target defaults:** newly created limb groups start with a floor-level support target rather than the drone target system's historical floating default.
- **Target reward geometry:** ordinary limb target progress and success use full 3D distance to the same routed core objective exposed to the policy. Elevated targets therefore require vertical progress. The model's binary inside-radius cue now uses the same 3D definition; the old horizontal-only inside flag that could report success underneath an elevated target has been removed.
- **Target objective separation:** signed full-3D target progress is no longer multiplied by posture/gait quality. The navigation objective says where to go; core drag, uprightness, planted support, foot slip, collision and torque cards independently describe how to get there. Moving away remains fully negative.
- **Climb shaping:** an elevated target can pay reversible reach potential, one-time real climbable-latch discovery reward, and high-water ascent reward while latched. Continued wall-hanging without progress has no renewable reward source.
- **Climb/reward conflicts:** positive hip-overstretch onset is relaxed only in genuine climb context; obstacle-approach punishment is reduced/disabled by climbing context/preset rather than globally weakening collision safety.
- **Obstacle perception:** limb workers receive multi-ray wall clearance plus direct target-path blockage and wall-top-relative-height information.
- **Support-surface sensing:** the downward ground probe excludes the articulated body but uses world collision geometry, so platform/box tops can become the support surface after ascent rather than always referring to the room floor.
- **Stock plantar contact:** profile v12 gives every stock distal limb a real 0.24 x 0.06 x 0.24 m rough box sole instead of relying on the rounded lower-capsule cap as the entire floor contact. The sole is authored flat in the neutral pose, offset beyond the lower capsule by its proximal support radius plus a 3 mm separation gap, and included in spawn/support geometry. The old v11 stock sole centered on the capsule tip is repaired because that layout physically overlapped the two shapes.
- **Sole orientation observability:** each limb exposes the terminal sole-up vector directly in core-local coordinates, so PPO does not have to reconstruct plantar orientation from the full articulated kinematic chain before it can learn a flat plant.
- **Ground-locomotion reward sign:** an otherwise ideal worker that stands still outside the target radius is net-negative under the stock ground deck. Survival/upright/height/support shaping can help discover a usable stance, but they cannot by themselves make an away-from-target episode profitable. Positive target progress remains fully available to rough leg-supported locomotion, but while the chassis itself is load-bearing it is reduced to a 10% recovery hint so rolling/crawling cannot out-earn the core-drag cost.
- **Grip spring geometry:** a physical end effector no longer springs its node/shape center onto the target surface. Acquisition stores an owner-side material point on the actual end-effector support surface and applies the bounded equal/opposite spring between the two material anchors, avoiding an active force that tries to bury the sole in walls.
- **Limb CPU diagnostics:** the expensive 420-feature pairwise/rank audit remains available but is sampled at lower cadence/size, and self-correlations are skipped. This changes diagnostics only, not PPO updates or policy inputs.
- **Limb inference hot path:** live physics decisions run the 420-input actor only. Critic values needed by PPO are reconstructed on the detached optimizer thread from the exact frozen producer-policy snapshot before GAE, so action selection no longer spends a second network forward pass on a value that cannot affect the body. Deterministic runtime/evaluation prediction is actor-only too.
- **Settle/reset hot path:** the 0.35 s startup settle no longer rebuilds sensors and the complete observation tensor at the physics rate. No action/reward consumes those intermediate snapshots, so the coordinator holds neutral commands and captures once when the first real decision begins.
- **CCD scope:** the stock core and four distal contact links retain swept CCD, while the four protected proximal links use ordinary discrete collision. This removes unnecessary swept-collision work without changing the contact-bearing foot links.
- **Planted-foot semantics:** when a physical terminal sole exists, only contacts generated by that terminal CollisionShape count as foot support/slip. Lower-leg/shin scraping remains a real collision but no longer masquerades as a planted foot in observations/rewards.
- **Slip shaping:** foot-slip cost is measured tangentially at genuine load-bearing sole contacts. The stock penalty now treats roughly 1 m/s of planted-foot skating as a major fault rather than almost-free translation, while clean target progress still dominates.
- **Evaluation retention:** the deterministic limb evaluator uses actor means, grippable walls, full-3D target semantics, joint-only smoothness, and includes a dedicated `climb_platform` scenario. A walking-only policy can no longer be selected as Best without ever being tested on climbing.
- **Episode survivability:** ordinary falling is not an immediate limb-training termination condition, allowing direct-actuator exploration to recover from bad poses.
- **Rotational steadiness reward:** pitch/roll chatter and rapid yaw reversal are discouraged while sustained yaw turning is intentionally free.

## Still requires runtime evidence

- Whether the 1.10 m grip perception radius is the best value for the stock limb reach and the actual Jolt broadphase/query behavior in crowded scenes.
- Whether the activation-scaled grip spring/damping/breakaway values remain stable when two or more limbs attach to different wall points while the policy moves aggressively.
- Whether the new flat sole footprint eliminates the visible skating/rolling contact in live Jolt simulation under aggressive learned joint torques; static geometry/material/contact attribution is now coherent.
- Whether the 190 deg/s horizontal hip slew fully removes the visible chassis chatter in live Jolt simulation; static code inspection found no second hidden horizontal force or self-collision source.
- Whether full-strength signed target progress causes a crawling local optimum in rollout data. The objective is now deliberately ungated; separate locomotion cards must suppress bad travel styles empirically.
- Whether PPO with the 64-unit hidden layers learns the intended sequence (approach -> reach -> latch -> transfer support -> ascend) at a useful sample efficiency. This cannot be proven statically.
- Whether climb reward magnitudes need further tuning after real rollout distributions are available. Their event/potential structure is non-farmable by construction, but relative scale is empirical.
